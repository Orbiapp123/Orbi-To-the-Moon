Layer 1

Frontend

A lightweight, no-framework stack keeps the game fast, auditable, and easy to embed in an iOS WebView wrapper.

Wallet Integration

The Phantom wallet SDK provides a window.solana object. Users connect once and sign transactions without leaving the app. All key management stays in Phantom — Orbi never touches private keys.

// Connect Phantom wallet const provider = window.solana; if (provider?.isPhantom) { const resp = await provider.connect(); const pubkey = resp.publicKey.toString(); console.log("Connected:", pubkey); }

Layer 2

Python Backend

FastAPI serves low-latency REST endpoints. A background indexer listens to Solana events and keeps the database in sync.

Responsibilities

  • ▸ Index on-chain events (chest purchases, marketplace trades, staking deposits)
  • ▸ Store item metadata: rarity, accessories, chest type, owner history
  • ▸ Compute and cache leaderboard rankings every 24 hours
  • ▸ Serve player profiles, inventory, energy/hunger bar state
  • ▸ Validate farm state transitions (wheat → milk → cheese logic)

Layer 3

Solana Smart Contract (Rust + Anchor)

All game logic that involves real value — registration, chest purchase, marketplace trades, staking — lives on-chain. Rust guarantees it can't be tampered with.

On-chain Instructions

  • register_player Transfer 1 SOL entry fee, mint Moon NFT to player
  • buy_chest Burn STR → emit chest open event, roll rarity on-chain
  • list_item Escrow item NFT into marketplace PDA, set SOL price
  • buy_item Transfer SOL to seller (99%) + dev wallet (1%), release NFT
  • stake_str Lock STR in PDA, record unlock timestamp + yield rate
  • claim_rewards Verify unlock time, transfer STR from treasury, close PDA

Sample: Anchor Program Structure

// Anchor smart contract (Rust) use anchor_lang::prelude::*; declare_id!("OrbiXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX"); #[program] pub mod orbi { use super::*; pub fn register_player(ctx: Context<Register>) -> Result<()> { let fee = 1_000_000_000u64; // 1 SOL system_program::transfer( CpiContext::new( ctx.accounts.system_program.to_account_info(), system_program::Transfer { from: ctx.accounts.player.to_account_info(), to: ctx.accounts.treasury.to_account_info(), }, ), fee, )?; let player = &mut ctx.accounts.player_account; player.owner = ctx.accounts.player.key(); player.level = 1; player.xp = 0; player.energy = 100; player.hunger = 100; Ok(()) } }

Development → Mainnet Pipeline

🧪

1. Local Testing

solana-test-validator spins up a local blockchain. Anchor tests run against it using TypeScript test harness. All instructions tested before any real funds.

🌐

2. Devnet Deployment

Program deployed to Solana Devnet for integration testing. Frontend and Python backend connect to devnet RPC. Phantom set to devnet for QA.

🚀

3. Mainnet Launch

Program upgraded to Mainnet Beta. LP tokens burned on Raydium. Program upgrade authority optionally transferred to a multisig for trustlessness.

Security

Security-first by design

Every architectural decision was made with the threat model in mind.

1

Non-custodial Wallets

Orbi never stores or requests private keys. All signing happens inside Phantom on the user's device. The backend only ever sees public keys and on-chain events.

2

PDA Escrow for Marketplace

Listed items are held in a Program Derived Address (PDA) — not the developer wallet. Smart contract logic enforces that only the buyer's payment releases the NFT. No rug possible.

3

Anchor Constraint Checks

Anchor's #[account(mut, has_one = owner)] constraints prevent any wallet from acting on another player's accounts. All authority checks are compile-time enforced.

4

Locked Liquidity

LP tokens are burned at launch on Raydium, making the liquidity pool permanently locked. Players can verify this on-chain — no team can rug the pool.

5

Bot Mitigation

Energy/hunger bar limits are enforced both in the backend (API rate limits) and on-chain (timestamp checks in smart contract state). Bots gain no economic advantage within the cap.
